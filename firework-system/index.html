01 / Overview

A pyrotechnics rig that plays like an instrument.

A concert stage can hold hundreds of emitters. Firing them one at a time is not a show, so this system groups them into named sequences that fire with one action.

The Firework System is one of the managers inside a larger concert platform. A small C++ class plugs fireworks into the platform’s shared timeline framework, and a Blueprint manager holds the sequencing, venue, and audio logic.

That split gives the system a clear shape. The timeline only records which action fires and when. The sequence decides which emitters respond, with what delay and which settings. The emitter applies those settings to its own effect.

Because the rig is addressed by tag, a sequence names the emitters it needs rather than positions in the level.

  • Authored shows13 tiers holding 117 sequences and 328 steps across two venue setups.
  • Rig445 placed emitters across those two venues, each with one unique tag.
  • EffectsFour emitter families covering bursts, continuous streams, aerial shells and flame.
  • DriversManual performance, audio automation, and offline render.
02 / Show structure

Sequences as data, addressed by tag.

Every look is a nested list: a tier of sequences, sub-sequences with a start delay, and steps that name their targets and settings.

  • TierA themed group of sequences for a venue, such as large spark bursts, smoke, or confetti.
  • Sub-sequenceA named part of a look with its own start delay.
  • StepThe tags to fire, an accumulative delay, an aim on each axis, and the settings for that effect type.
  • Draft overridesConcert-wide colour, density, velocity, height, spread and burst life can be adjusted without editing a sequence.

03 / Effect families

Four emitters, one parent class.

Each family derives from a shared base, so a sequence can fire a mixed rig through one call.

Single burst

Sparks, smoke, steam, confetti

Short Niagara bursts with control over height, speed, colour, cone angle, vertical acceleration and life. Sequence values are passed in as Niagara user parameters.

Continuous

Spark and smoke streams

Fountains that run for as long as they are held. On the timeline, the length of the press is written back into the key, so a held effect replays for the same duration.

Explosives

Aerial shells

Eight shell and burst types, including peony, chrysanthemum, crossette, ring and palm. A trail actor launches with its own movement and rotation, then explodes on a timer. Bursts can also take the shape of a skeletal mesh.

Flame

Cached flame jets

Flame effects play from Niagara simulation caches, with a cache picked at random so repeated jets do not look identical.

04 / Authoring

Three ways to build a show.

Venue sequences are built in the editor, users can create their own inside the application, and an operator turns either into a timeline.

01

In the editor

Venue tiers are authored as nested structured data. Each venue gets its own named categories and sub-actions, loaded with the level.

02

In the application

A custom firework panel places emitters by cursor trace, adjusts them with transform gizmos, assigns tags, previews a sequence, and saves it all to the concert draft.

03

By performing

An operator triggers categories during playback and each action is recorded as a key. Favourites and exclusions shape which sub-action a category picks.

05 / Playback

One action, three drivers.

A key stores an action rather than burst settings, so a live press, an automated cue and a render event all reach the same firing path.

  • ManualActions are built from each venue’s category assets, then played and recorded while the show runs.
  • AudioAutomation listens to the audio analysis engine and uses bass and mid levels with range and responsiveness settings. It can also record the keys it fires.
  • ReplayEach wait is recomputed from the video’s playback time, and late keys catch up immediately.
  • Offline renderKeys become event track keys in a Level Sequence generated at runtime, which call the same play action.
06 / Engineering notes

What made it hold together.

Architecture

Built on a shared timeline

Recording, layers, replay and draft saving come from the same manager framework used by other concert systems. The fireworks class adds only what is specific to it.

Addressing

Tags over hard references

Steps target tags rather than transforms, which keeps authored data separate from the level. Emitters are found by tag when a step fires.

VFX mix

The right tool per effect

Niagara handles sparks and smoke, Cascade handles shell bursts, and simulation caches handle flame. Sequences use all of them through one vocabulary.

Built on

Standing on good parts

The cold spark and shell effects and stage hardware come from Epic’s DMX Fixtures content, and the shell trail builds on an existing fireworks asset. The sequencing, control and timeline layer is what ties them together.
